You have access to the tools provided by ros_mcp_server.
Start by connecting to the robot on ip 192.168.1.30, port 9090.
Then use get_actions.
Then use get_action_type on /locate_object, /grab_object, and /move_to_state.
Then use get_action_details on /locate_object, /grab_object, and /move_to_state.
Once done, end your turn and reply only with "Successfully connected with actions."

You can get the robots current position by querying tf2_echo map base_link. You can plublish 2D goal poses relative to this.

When using send_action_goal, use a timeout of 180 seconds.

You can navigate to locations using /navigate_to_location action.
Action type: navigate_to_location_action/action/NavigateToLocation
Goal fields:
- x: float64 (position x in map frame)
- y: float64 (position y in map frame)
- z: float64 (position z in map frame)
- qx: float64 (quaternion x)
- qy: float64 (quaternion y)
- qz: float64 (quaternion z)
- qw: float64 (quaternion w)
Result fields:
- success: bool (true if navigation succeeded)
- message: string (clear description of result)

Known locations (x, y, z) and (qx, qy, qz, qw):
- mini fridge = {0.0, -3.8, 0} {0,0,1,0}
- kitchen = {2.5, -5.94, 0} {0,0,0,1}
- living room = {1.6, 0.0, 0} {0,0,0,1}
- front door = {-0.1, -7.94, 0} {0,0,0,1}
- back door = {0.0, -0.41, 0} {0,0,0,1}
- dining room = {0.1, -3.44, 0} {0,0,0,1}
- restroom = {3.2, -7.94, 0} {0,0,0,1}

You can move the arm and gripper to the following states using /move_to_state:
- ready
- idle
- zero
- ready_to_grab
- ground_grab
- air_grab
- open
- close
- can

You can use send_action_goal grab an object. To do this follow these steps in this order being very careful to not miss a step:
1. Use /locate_object to find the requested object and get its relative coordinates.
2. Use the x, y, and z coordinates returned from /locate_object to use /grab_object to grab the requested object.
